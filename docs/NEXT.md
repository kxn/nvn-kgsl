The public/private two-root handoff and its integrity checks are described in [PRIVATE_HANDOFF](PRIVATE_HANDOFF.md). Preserve and inventory every unfinished candidate as well as integrated work.

The first work is to make the new standalone checkout build reproducibly without a D2R checkout. Then continue these existing functional-family tasks, without losing their qualification boundaries:

- **Formal graphics storage gate:** integrate default-OFF host/build plumbing around the qualified raw SSBO runtime. Validate exact boolean options, dependency forwarding, source closure, source identity and ABI1/ABI2 OFF/ON real NDK links. Register only the sidecar/native recipes that the normal producer actually published. Native192 does not replace the pending public original-source SSBO consumer tests.
- **FrontFacing GPU family:** finish the isolated authored qualifier for real faceness under winding/cull/origin state and replay. The candidate target is 384 draws, 640 submissions/completions, 512 full readbacks. These are planned counts until a fresh normal APK and actual device evidence prove them. No original-source support claim should be inferred from the HOST matrix.
- **Public depth-sampling family:** finish a 144-case proposed matrix over the actual source-backed SAMPLE and GatherR+FragDepth paths, three source depth formats, two shape/selected-mip cases, two origins, Direct/Copy/Call and updated-input replay. Reuse the established runner/oracles; do not implement a second transport or replace original shader semantics. Array/compare/FETCH/SIZE qualification remains separate.
- **Vertex driver parameters/dynamic UBO:** independently implement the actual IR3 driver's parameters and residual native UBO slots as a complete family, with typed metadata and explicit reject limits. Distinguish DrawID, vertex base, instance base and maximum vertex. GPU indirect parameters cannot be implemented by CPU reading a GPU-indirect buffer. Existing research candidates are not integrated qualification.
- **Current real-workload resource family:** investigate the v21 target-4/format-50 non-packaged two-layer boundary, enumerate the associated 2D/array/mip/flags/source/native roles, and extend the family using independent layout and transfer evidence. Do not patch only the 2100×2100 observation or synthesize an expected answer.
- **Real workload combination check:** after qualified family changes, generate a fresh canonical external build using the complete source/compiled catalogues and explicit feature options. Verify before installation, retain the original signing/data policy, run on the qualified device, and report the first unsupported boundary and actual Draw/Submit/Present counts. The intended milestone remains a real frame through the independent backend.
