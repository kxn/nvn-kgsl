> 历史文档 / Historical record. 本文保留当时结论与失败，不代表当前支持范围。当前状态以 [STATUS](../STATUS.md) 为准；旧证据的公开边界见 [HISTORICAL_EVIDENCE](../HISTORICAL_EVIDENCE.md)。本地路径和设备标识已替换，少量SDK原指令摘录已改为语义描述。

本次结论：可以开工，目标应定义为**独立的 NVN 兼容用户态 GPU 驱动**。它向程序提供 NVN 的 ABI 和行为，向目标 GPU 产生原生命令、资源描述符与着色器机器码，通过现有内核驱动提交。D2R 负责提供真实调用、资源和集成验证；它的内部表示、兼容简化及游戏策略不定义新库的架构或 NVN 规范。

用户补充已纳入：没有官方 NVN 资料，只能使用现有项目黑盒测试与公开资源。源码入口、shader 复用、证据分级和可直接拆分的 T01–T08 实施任务见 [实施细化](implementation.zh-CN.md)。不把取得官方文档或原机环境作为开工条件。

这里的“直接使用硬件接口”分为两层：用户态构造目标 GPU 的命令和状态；内核接口负责地址空间、分配、上下文、提交与完成。第一款设备建议使用已连接的 Adreno 735 / KGSL。无需把目标扩成 CPU 模拟器，也不需要首先替换系统内核、GPU 固件或系统图形驱动。普通应用 UID 的实际权限和提交能力仍须验证。

本结论遵循用户在调研过程中的最新澄清：不沿着 Vulkan 的实现继续研究，不把原项目实现混入新目标。此前已经读取的相关资料只保留为审查历史，不构成建议的执行依赖。

1. **ZIP 很有价值，但不能原样作为这条新路线的实施清单。**

   已阅读主体设计、四份契约、四份审计、阶段与资格要求，以及六组共 524 条 API 映射；核对接口、参考模型和补丁来源。HTML/Markdown/API JSON 的重复表示用于交叉检索。包内计数为 523 个 resolver 名称加 BootstrapLoader，216 个名称有静态调用点，46 项标记 ABI-GATE；这些不是完整 NVN 版本规范，也不是实现覆盖率。

   值得保留的是对象身份与允许写入范围、命令与控制内存、参数消费时点、物理别名、CPU/GPU 可见性、同步与查询、提交失败分类和资源退休的约束，以及对应反例。它们不会因为使用直接硬件路径而消失。

   需要重新设计的是 Turnip 同 DSO bridge、复用其设备初始化/队列对象、内部 pipeline layout，以及基于这些依赖的 V01–V12。原文四 bank、32 个 buffer slot 和 18.25 KiB 表快照只能当候选表示；应从 NVN 实际资源语义和目标硬件能力重新决定，不能因 ZIP 写了具体数字就固化为通用 ABI。

   清单仍含泛化占位描述，例如若干条目只有“字段规范化/对象操作”，也混有其他 GPU 的说明。同步条目的旧 timing 和新 FenceEpoch 契约还需要统一。参考模型只验证部分反例，例如 memory model 的 prepare 保存 pending，却没有实现完整的 pending 依赖规划。不能据模型通过认为生产内存协议已完成。

2. **硬件执行层有公开入口，也有可独立复用的基础组件。**

   2026-10-23 只读 ADB 查询得到：SoC `SM8635`、GPU `Adreno735`、API 36、内核 `6.1.145-android14-11-maybe-dirty`、实际页大小 4096，存在 `/dev/kgsl-3d0`。查询 chip_id 的该 sysfs 路径不存在，精确芯片修订和能力要通过后续属性查询确认。设备节点存在和权限位不等于普通应用已通过 SELinux、分配、提交和同步验收。

   Qualcomm 公开的 [KGSL UAPI](https://github.com/qualcomm-linux/kgsl/blob/gfx-kernel.le.0.0/include/uapi/linux/msm_kgsl.h) 包含 context 创建/销毁、GPU 内存分配/导入、`IOCTL_KGSL_GPU_COMMAND`、context timestamp 等待和 fence 事件等接口。实际采用哪组 ioctl、flags、缓存属性和错误语义，必须匹配手机内核，不能把公开最新头直接视为该机合同。已读取该文件，Git blob SHA 为 `036be5ab25a9b647c4003bf0f30458d5d27329a3`。

   本机已有 Mesa 26.2.5 源码。以下组件位于 Freedreno 公共目录，可以研究其独立链接边界，而不依赖现有应用的渲染后端：

   | 组件 | 可以解决的问题 | 仍须新实现的部分 |
   |---|---|---|
   | `src/freedreno/registers/`、`common/freedreno_pm4.h` | 寄存器、命令格式、芯片信息与编码生成 | NVN 状态如何变成正确完整的硬件状态、芯片限制与工作顺序 |
   | `src/freedreno/fdl/` | Adreno 图像布局、格式与视图编码 | NVN 原始布局、别名、转换和 CPU 观察语义 |
   | `src/compiler/nir/`、`src/freedreno/ir3/` | 共同着色器 IR 与 Adreno 编译/汇编/反汇编 | NVN shader 输入翻译、资源 ABI、阶段接口连接和程序状态 |
   | `src/freedreno/decode/` | 已有命令解码、反编译和重放工具 | 新 NVN 语义捕获、资源初值与观察点的对照合同 |

   实际读取的 Meson 文件已将 `freedreno_common`、`freedreno_layout`、`freedreno_ir3` 声明为独立静态库，且有相应生成器和依赖。这证明存在可拆用的构建单元，尚未证明本次独立 Android 库已经构建或链接成功。NIR 的 lowering 顺序、IR3 的驱动参数/变体要求和图形阶段连接仍是工作的一部分；IR3 不直接识别 NVN 的 NVIDIA 着色器二进制。

   还找到一个重要现成起点：`src/freedreno/decode/replay.c` 的 `FD_REPLAY_KGSL` 路径，直接打开设备、分配内存、创建 context、提交 GPU 命令并等待 timestamp；对应 Meson 目标明确支持 KGSL。它是独立命令重放工具。应优先验证和利用其现有能力，不另造一套重放器或命令解码器。

   该工具不能直接充当生产驱动：当前 KGSL 路径有 1 GiB 单分配、固定地址期望、页大小假设及工具式失败处理；`generate-rd.cc` 本身还是等待反编译输出替换的占位文件。首批实验需要小而受控的输入和明确的实际地址，不盲目运行默认大分配，也不声称工具已经在该手机验收。其引用路径中的 `msm_kgsl.h` 是内核 UAPI，不意味着执行图形 API。

3. **新架构应围绕 NVN 自己的语义建立。**

   ```text
   NVN 调用者（独立测试程序 / D2R / 后续其他程序）
                    ↓
   NVN ABI、对象与命令录制层
                    ↓
   NVN 资源、执行顺序、同步与查询语义
                    ↓
   Adreno 原生状态 / 描述符 / PM4 命令构造
                    ↓
   KGSL 上下文、地址空间、提交与完成
                    ↓
                  Adreno GPU

   NVN shader → 已验证的语义翻译 → NIR → IR3 → Adreno 机器码
   Android 窗口 → 原生 buffer 导入 / acquire-release fence → 出图
   ```

   对外兼容函数、返回值、对象字节及可观察行为；对内允许缓存、合批和重新组织命令。setter 可以只改变 CPU 状态，一次 draw 可以只发变化的硬件状态；不要求一次 API 调用对应一条硬件命令。

   NVN 核心不得包含游戏名、场景判断或玩法。D2R 接入层只提供入口重定向、地址空间/宿主回调、窗口和测试输入。GPU 着色器翻译属于图形兼容工作，不能引入模拟器 CPU 解释器、JIT 或系统服务运行时。

   存储表示应区分逻辑身份、实际 backing、GPU 地址、内容版本与编码版本。静态资源尽早生成可复用描述符；draw 消费已知引用及变化集合，避免重复查找全局资源。同步和在途寿命不能随缓存命中省略。原包 18.25 KiB 表若每帧变化 2300 次会复制约 41 MiB，这只是条件算例，但足以要求在确定 ABI 前验证更新字节和在途版本成本。

4. **建议按六个可验收的阶段开工。**

   | 阶段 | 交付物 | 完成判据 |
   |---|---|---|
   | 0：独立构建与目标合同 | 独立库/测试 APK、源码与工具链 pin、目标 NVN ABI/profile、设备能力清单 | 独立 Android 产物和依赖表可重建；运行时不依赖原项目渲染器；未知能力明确列出 |
   | 1：直接硬件基础 | 小 BO、context、命令内存、提交记录、完成与回收 | GPU 实际写入哨兵，经正确完成和缓存边界 CPU 读回；超时/失败不提前释放资源 |
   | 2：独立图形与编译闭环 | 固定清屏、带常量与纹理的 VS/FS、独立 CS、状态恢复测试 | 原生像素/字节正确；改变资源和插入内部操作后仍正确；不能用清屏代表 shader 完成 |
   | 3：NVN 最小真实语义 | 对象、双 arena、Copy/Call、Program、buffer/texture/sampler、Draw/Dispatch、Barrier/Fence | 按证据等级比较项目黑盒、公开逆向与新库；记录无法鉴别和冲突的语义；独立测试不依赖 D2R 私有状态 |
   | 4：真实输入与上屏 | D2R 的真实调用、资源初值和 shader；Android 原生窗口缓冲/fence 桥 | 先有界真实重放，再实验副本执行真实 ARM64 游戏模块、呈现及生命周期；分别记录证据 |
   | 5：能力扩展与优化 | 按 NVN 功能矩阵补格式、间接绘制、查询、事件、复杂 shader、稀疏/互操作等 | 精确版本能力表和回归语料；跨场景验证后，再按 profile 优化 GMEM、复用和调度 |

   阶段 0 同时准备 NVN 语义鉴别用例，不必等整套前端写完才验证硬件。阶段 1 的普通 BO 不依赖旧 f830 驱动、任意宿主页面导入或原生 ASTC 资源包。阶段 2 可以先采用易核对的 sysmem 基线，但完整硬件初始化和 cache 协议不能省略；阶段 5 再衡量 tile/GMEM 的收益。

   第一批具体任务应是：固定一个 GPU 修订、整理公共组件独立构建闭包、验证已有 KGSL 重放工具的适用性、补最小有界的直接提交测试，并为 Copy/描述符消费/Fence 复用建立项目行为对照和语义证据表。当前项目接管原 NVN，不能把项目结果称为原 NVN 的原始行为。首批不必生成 524 个空入口或立即修改 D2R 启动流程。

5. **“最好”的目标要靠多项证据共同衡量。**

   正确性包括像素、buffer 字节、同步次序和公开返回值；兼容性按 NVN 版本与特性组合记录；性能分别记录完整 CPU 工作、GPU 时间、内存、提交延迟和稳定性。使用直接接口给了优化空间，但编译、资源转换和正确依赖仍有成本，不能预先承诺全场景最快。

   Simpleperf/Perfetto、设备可用的原厂 profiler，以及 Freedreno 已有解码/重放工具优先。先验证每种工具对直接 KGSL 进程的实际覆盖；原有 API 层捕获不能自动看到新库的全部原生命令。只有现成工具确实不提供 NVN 调用语义、资源版本/初值等信息时，才增加有界的语义记录，不重写计时或采样工具。

   后端优化不以立即涨帧作为唯一保留条件：保留可证明减少工作、成本有界且无明显正确性退化的方案，同时如实记录整帧收益。新基线必须来自新库及对应设备，不能继承旧项目的性能结论。

6. **现在需要工程补齐语义证据和测试语料，不需要用户提供不存在的 NVN 文档。**

   已有：可读写项目、独立分支/worktree、NDK r28c、本机源代码和部分既有工具链、连接的 Adreno 手机、D2R 资源处理与原生执行验证环境。现有工具不都在默认 PATH，新工作树也不自动拥有主目录 `.local`；开工时应显式指定工具路径和独立输出，不能共享可变构建目录。原始游戏输入和产物清单在实际接入前重新核验，本次未重建或运行游戏。

   在现有项目的调用边界取得真实 shader、资源初值、状态变化和读回结果，结合公开逆向建立逐项证据表。已有行为、硬件依据和待验证假设分别记录；复制同源代码的多个项目不能算多份独立证据。

   shader 前端可以复用仓内 Maxwell 翻译库，SPIR-V 作为编译中间格式接 NIR/IR3。必须新增严格的输入/状态 accessor 和资源 lowering，不能把现有 PC 配对事实表、固定槽位与默认值固化成 NVN 通用规范。手机端新 shader 编译另设资格验证；离线覆盖已知样本不等于通用运行期能力。

   目前可直接开始独立构建、shader 输入语料和 KGSL 基础验证。后续扩大兼容范围时，再增加第二个独立调用者或不同版本的样本。首轮使用现有 Adreno 735，不要求再购设备；未来 Mali 属于另一个硬件后端。ZIP 提到的 v2 背景包若以后取得可再归档，不阻塞当前工作。
