# Next BC sampling closure: sRGB, selected subresources, real arrays/mips

This is an implementation plan, not an expanded capability or GPU result. Current public BC24 is UNORM ordinary2D/mip1/layer1/nearest-clamp only. Root's observed game resource is format70 (0x46 RGBA_DXT1_SRGB), target4,128×128×84 layers,7 levels; that observation does not identify the shader/view/sampler consuming it. No game-address or source-hash special branch is proposed.

## Existing reusable mechanisms, checked in current source

- Public enum source: `third_party/nvn/nvn.h:479..482` gives 0x45 RGB_DXT1_SRGB,0x46 RGBA_DXT1_SRGB,0x47 RGBA_DXT3_SRGB,0x48 RGBA_DXT5_SRGB. These are distinct formats, not linear-format aliases.
- Common Mesa FDL26.2.5 `fd6_format_table.c:309..315` already supports DXT1_SRGB/DXT1_SRGBA/DXT3_SRGBA/DXT5_SRGBA. `fd6_view.cc:257` derives the A6 texture SRGB descriptor bit from `util_format_is_srgb(args->format)`; its DXT1_RGB/DXT1_SRGB case preserves alphaONE. Reuse normal original FDL, not a custom descriptor encoder, CPU decoder or rewritten compressed data.
- Current `runtime_fdl.cc` format map admits only UNORM0x41..44; its image path already obtains all mip offsets/pitches/layer strides and creates the actual FDL selected mip/layer view. The allocation's target remains2D/array metadata. FDL `FDL_VIEW_TYPE_2D` also represents an array allocation with selected layer ranges; do not invent a separate FDL view enum or derive NVN shader dimensionality from layer_count alone.
- `texture_bc_shadow.c:17..33` already builds ONE raw-block dispatch per mip, with `region.layers=source.layers`. GPU z dispatch batches the array layers. Thus7 mip levels do NOT require7×84 separate dispatch BOs. `nn_block_copy_region` already has `base_layer/layers`; no new GOB/copy shader is needed for a selected layer range.
- The shadow owns one native compressed storage BO, one shared code BO, one uniform+dispatch pair per mip, and borrows the canonical BO. Raw conversion preserves canonical pool bytes/aliases and changes layout only; no CPU pixel conversion. Existing full dependency barriers and retire/unknown-owner ledger apply unchanged.
- Current raw shadow metadata can upload2D arrays/mips, but sampled validation explicitly rejects array/sRGB/multi-mip views. Core admission is stricter: `pipeline_resource_queries.c:66`, `nvn_pipeline_draw_prepare.inc:175,191`, `texture_bc_shadow.c:130`, `sampler_state.c:43`. Those checks are independent and must not be removed globally.
- True sampled arrays additionally require a normal source specialization and NIR support: `shader/maxwell/Program.cs:96..99` currently admits only1D/BUFFER/2D; `shader/nir_bridge.h:79,125` rejects array image operations. Resource descriptor arrays/dynamic descriptor indexing remain a different unsupported feature and need not be opened.

## Smallest implementation sequence

1. **sRGB ordinary2D, no new compiler:** extend only the normal runtimeFDL facade's exact format map0x45..48 to the corresponding original Mesa pipe formats. Rebuild normal runtimeFDL/checks; no NIR/compiler change is needed for hardware sRGB decode. Extend BC source admission by exact format traits, keeping RGB-vs-RGBA alpha behavior. Reuse validated source/FDL block widths/height/cpp; do not keep the old `format<0x43 ?8:16` shortcut for sRGB formats. Keep all current owner, RT, sampler, dimension and unknown-query gates.

   GPU test must contain nonzero/non-one RGB endpoints. Current black/white/red/green endpoint controls cannot distinguish sRGB decode from UNORM. Author legal RGB565 endpoints and compare their known endpoint values through the standard sRGB-to-linear transfer into a LINEAR UNORM RT; transparent BC1RGBA alpha and BC1RGB alphaONE remain separate. This is a closed authored oracle, not a CPU compressed-image decoder. Exercise the actual source/descriptor and source-update/replay path. Prove bounds/tolerance from endpoint quantization and actual shader controls; do not widen tolerance to hide differences.

2. **Single selected mip/layer as an actual2D view:** coordinate with the registration/subresource module's explicit selected target/mip/layer metadata. An array allocation with one selected layer must not automatically become a2D resource; the actual NVN TextureView target selects the shader domain. For an explicitly requested2D view, pass the original allocation geometry plus actual mip/layer selection to FDL, preserve canonical/full-owner spans and use original `base_layer` raw-copy support. Current FDL allocation target field and actual NVN view target need distinct interpretation at the typed boundary; no need to fabricate descriptor fields.

   First tests: layers0/1/83 and levels0/1/6 of a128²×84,7-level allocation, with distinct authored colors per layer and mip; partial updates and same-handle late registration. Independent expected values come from the selected source subresource, never from reading GPU output as its own oracle. Reuse original a767 bounded2D shader where its actual query requirements match the registered2D subview. The original array/canonical allocation size and alias semantics never change.

3. **Real2D-array shader domain:** expose actual registered target4/selected array view as the translator's typed2D-array enum, obtained from the pinned frontend definitions rather than a guessed integer. Extend the strict normal frontend/NIR bridge only for scalar2D-array texture operations actually emitted/validated. Preserve rejection of resource-variable arrays, dynamic descriptor indices, unknown operation kinds, MS/depth/image writes and unrelated dimensions. The existing common NIR→IR3 compiler already contains array-coordinate lowering; use it and asmroundtrip rather than writing another translator. Verify actual coordinate counts, TXS result dimensionality and per-binding NIR resource semantics.

   This compiler-source change requires a fresh normal `build_ir3` and regeneration of dependent original compute/conversion/graphics checks. Old GPU binaries remain history unless byte equality is independently established. Do not mutate old build records. Runtime must match the actual array specialization; an old2D archive variant cannot satisfy it. Authored native GLSL array shader may qualify hardware independently, but is not proof that a real original game array shader was translated/consumed.

4. **Mips/LOD:** admit actual selected levels only after FDL descriptor range/base-lod semantics, source view dimensions, explicit LOD/fetch operands and sampler min/max/bias/mip-filter fields are checked against existing common Gallium/register sources. Extend sampler metadata/gates and actual recipe selection together; simply deleting `levels!=1` is insufficient. Start nearest mip/explicit selected levels with distinct mip colors, then linear/trilinear/filter modes in a separate bounded GPU matrix. Alpha behavior and sRGB RGB-only decode stay independent.

## Ownership, work and capacity conditions

- The current foundation uploads every source mip/layer even when the sampled view is smaller. This is correct but potentially expensive for84 layers; don't present it as optimized. Existing `base_layer/layers` raw-block support permits a later proven selected-range conversion, with exact native destination offsets from FDL.
- Mip count changes actual BO/resource upper bounds: native storage+code+2 BOs per dispatched mip, borrowed canonical once, plus private graphics job and other actual resources. Expand core flattening/reference preflight from single-mip constants using this actual count; retain dedup, capacity checks, no-allocation preflight, rollback and unknown-completion retention. Do not replace this with a large per-draw constant causing false queue-budget failures.
- Source/caller metadata ownership remains separate from submitted GPU resources. Actual immutable enqueue descriptor/sampler snapshot must answer queries and supply the same views for native materialization. No archive-first query answer or implicit current-object pointer.
- Cached native storage/code reuse needs exact stage/specialization/view/source-update identity, refcounts and retirement. Do not introduce a dirty-tracking shortcut that misses CPU alias writes. Measure eventual recurring work with Android tools; current correctness tests are not a performance result.

## Immediate next implementable batch

The sRGB ordinary2D facade/shadow extension and explicit2D single-layer/mip-view consumer can be implemented without modifying the compiler or raw-block shader. Normal FDL metadata + HOST owners first, then ordinary-UID public GPU sRGB/subview cases. Real array sampling remains a separate strict frontend/compiler/runtime specialization batch; actual game shader binding and sampler state still must be observed/derived normally. Metadata acceptance of format70/target4/84×7 is not evidence of sampled consumption or a game frame.
