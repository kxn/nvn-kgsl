# Development conventions

1. Keep this repository focused on the reusable native NVN compatibility library. D2R is an optional external workload. Turnip/deko3d and hardware documentation are references; do not import their public API semantics as if they were an NVN specification.
2. Implement source semantics through KGSL/PM4/IR3/FDL and Android native presentation. Do not compile, link or fall back to Metal/Vulkan renderers. Offline SPIR-V descriptor conventions are allowed when their use and actual runtime dependency closure are recorded.
3. Use reconstructed declarations, public hardware documentation, separately evaluated reverse engineering, lawful local static inspection and observable tests with explicit evidence levels. A name/signature is not proof of defaults, lifetime, consumption timing or synchronization. Version the ABI/SDK scope. No guessing unresolved ABI.
4. Complete functional families. Before coding, enumerate supported inputs, operations, source/native roles, state combinations, lifetime and failure cases. Implement the coherent family, then qualify it as a group. A real workload reveals combination boundaries; it is not the entire implementation backlog.
5. Report resolver registration, CPU semantics, HOST/sanitizer checks, actual NDK linking, raw-native GPU qualification, public-NVN GPU qualification and real-workload execution separately. Never inflate one using another.
6. Unsupported combinations fail explicitly and transactionally. Do not return success for missing behavior, manufacture pixels on CPU, substitute a simpler shader, assume unknown query answers or modify gameplay to cross a boundary.
7. Preserve resource identity/aliasing, current input data on replay, immutable submitted state and in-flight ownership. Distinguish known rejected, accepted and unknown outcomes. Accepted or unknown work is never automatically retried or prematurely recycled.
8. Every normal build records source/tool/options/input/artifact fingerprints. Verify cache hits and deploy only the verified output. Original-game inputs are rebuilt from raw originals through the external project's declared pipeline; never layer manual patches onto processed binaries.
9. Use dedicated branches and isolated output directories. Parallel workers may develop independent candidates, but integrate shared files through one owner. Only one controller owns ADB/device operations. Freeze source and records from qualification build through run termination; changes require a fresh record where relevant.
10. Use existing GPU analysis tools before implementing replacement collectors. Profile the actual Android device for performance work. Keep correctness and whole-frame claims distinct from reduced instructions, memory traffic or synchronization. Do not require immediate FPS gains to retain a sound optimization with no significant regression.
11. Device tests are bounded. Stop the test package and verify exit after qualification; do not leave games running during analysis/build. Respect any external workload's normal save/lifecycle before stopping. Do not terminate unrelated services. Use configured device selectors, never checked-in private IPs.
12. Keep proprietary game/SDK code, extracted resources, source shader containers, generated derivative binaries, saves, signing keys, device identifiers and raw logs outside public version control. Authored data requires provenance; upstream code retains its actual license. Public text is newly written factual explanation, not a copied proprietary document.

Change reports state what changed, why, what exact tests ran and the remaining limitations. Each evidence record carries enough source/input/output identity to distinguish current verification from a historical proof. Preserve failed runs and their hashes; never edit an old result into a pass.

The local-only private companion preserves all excluded useful material and unfinished candidates separately. Follow [PRIVATE_HANDOFF](PRIVATE_HANDOFF.md); do not move its contents into public Git, and do not rewrite old path-bound hashes after relocation.
